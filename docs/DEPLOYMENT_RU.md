# Деплой AssetMind v031

## Переход с версии с инвайт-кодом

1. В Supabase, который подключён к этому Vercel-проекту, выполните обновлённый [harden_existing.sql](../supabase/harden_existing.sql) целиком. Он заменяет старую RPC-функцию на вариант с `p_portfolio_id`, сохраняя портфели и сделки. Старые записи приглашений остаются, но больше не используются.
2. Получите ID нужного портфеля: `select id, name from public.portfolios order by created_at;`.
3. Vercel → Project → Settings → Environment Variables: добавьте `DEFAULT_PORTFOLIO_ID` с выбранным UUID для нужных окружений.
4. Выполните Redeploy после SQL и настройки переменной. Между заменой RPC и деплоем старые запросы записи могут не работать, поэтому выполняйте переход в короткое окно без сделок.
5. Откройте сайт: вход больше не требуется. Любой посетитель может читать общий портфель и добавлять сделки.

Живая база и настройки Vercel в рамках этого изменения не обновлялись: их связь пока не подтверждена.

## Что подготовлено

- Node.js 22.22.2+ (ветка 22) или 24.15.0+ (ветка 24), npm 12.0.2.
- `package-lock.json` фиксирует зависимости; установка через `npm ci`.
- GitHub Actions запускает TypeScript, тесты, lint и production build.
- `vercel.json` задаёт Vite, установку закреплённым npm, `npm run verify` и папку `dist`.
- `npm run smoke` проверяет чтение портфеля без авторизации, не создавая сделки.
- `supabase/verify_deployment.sql` проверяет структуру и права без изменения данных.
- `supabase/seed_demo.sql` создаёт отдельный тестовый портфель.

Успешная сборка не подтверждает настройку живой базы, ключей провайдера или хостинга.
Runtime-зависимости проходят отдельный обязательный audit на high/critical. Полный audit также выводится в Actions.
После обновления Supabase до 2.116.0 и @vercel/node до 5.10.2 полный audit всё ещё сообщил о 6 уязвимых пакетах (1 low, 2 moderate, 3 high) в dev-цепочке @vercel/node: ajv/static-config, path-to-regexp, undici и esbuild/tsx. Это открытый пункт перед публичным релизом. Не используйте npm audit fix --force вслепую: он предлагает несовместимое понижение @vercel/node до 4.0.0. Нужна проверенная замена/обновление toolchain либо отдельно протестированные overrides; версия для закрытого тестирования не равна подтверждённому production-релизу.

## 1. Выбор Supabase

В подключённом аккаунте обнаружены две разные схемы. Выбирайте проект по структуре, а не только по имени.

Для этой версии нужны:
- `portfolios`: id, name, base_currency, created_at;
- `transactions`: portfolio_id, symbol, type, quantity, price, currency, timestamp, created_at, client_request_id.

Проект с обязательными `user_id`, `transaction_id`, `date` относится к другой архитектуре.
Не запускайте в нём эти SQL-файлы без отдельной миграции.

В подходящем существующем проекте:

1. Сделайте резервную копию существующих данных.
2. Откройте SQL Editor → New query.
3. Вставьте полный текст [harden_existing.sql](../supabase/harden_existing.sql), выполните.
4. Выполните [verify_deployment.sql](../supabase/verify_deployment.sql). Ожидаемые результаты указаны в комментариях.
5. Выполните [seed_demo.sql](../supabase/seed_demo.sql) один раз. Скопируйте выданный `default_portfolio_id` в серверную переменную `DEFAULT_PORTFOLIO_ID`. Можно использовать ID существующего портфеля вместо создания нового. Все посетители будут видеть и изменять именно этот портфель.

Для совершенно нового пустого проекта сначала используйте [schema.sql](../supabase/schema.sql), затем шаги 4–5.

## 2. Ключи

В выбранном Supabase откройте Settings → API Keys, скопируйте **secret key**.
URL проекта возьмите из Connect. URL и ключ обязаны относиться к одному проекту.
В Finnhub откройте свой аккаунт и скопируйте API key.

Вводите ключи непосредственно в Vercel; не публикуйте их в GitHub или чате.
Источник: [Supabase API keys](https://supabase.com/docs/guides/getting-started/api-keys).

## 3. Vercel

1. Откройте Vercel → Add New → Project → импортируйте `elcin31/assetmind-v031`.
2. Если репозиторий не виден, разрешите Vercel GitHub App доступ к нему.
3. Root Directory — корень репозитория; Framework Preset — Vite; Node.js — 22.x.
4. Настройки установки и сборки уже находятся в `vercel.json`. Не меняйте Output Directory на `src` или `public`.
5. Добавьте переменные для используемого окружения (Preview и/или Production):

| Имя | Значение |
|---|---|
| SUPABASE_URL | URL выбранного Supabase проекта |
| SUPABASE_SECRET_KEY | Secret key того же проекта |
| DEFAULT_PORTFOLIO_ID | UUID выбранного общего портфеля |
| FINNHUB_API_KEY | Ключ Finnhub |

6. Нажмите Deploy. Для закрытого тестирования ограничьте доступ настройками Deployment Protection, если они доступны в вашем проекте.
7. Если переменные добавлены после первой сборки, выполните Redeploy.
8. Проверьте, что Deployment получил статус Ready и API-функции созданы из папки `api/`.

Это деплой тестового MVP. Готовность публичного продукта требует проверки ограничений ниже.
Источники: [конфигурация Vercel](https://vercel.com/docs/project-configuration), [переменные окружения](https://vercel.com/docs/environment-variables).

## 4. Проверка после деплоя

На отдельном тестовом портфеле:

1. Откройте сайт в новой приватной вкладке: портфель загружается без ввода кода.
2. Обновите страницу: тот же портфель загружается автоматически.
3. Найдите AAPL: поиск должен вернуть инструмент. Проверьте получение котировки.
4. Купите 1 AAPL с явно указанной ценой и валютой USD.
5. Попробуйте продать 2 AAPL: запрос должен быть отклонён.
6. Продайте 1 AAPL: открытая позиция должна исчезнуть, сделки останутся в истории.
7. Проверьте запись задним числом и идемпотентность по [Supabase checklist](SUPABASE_HANDOFF.md).
8. Если котировки или история недоступны, проверьте ключ/тариф Finnhub. Пустые или частичные данные не подтверждают работу провайдера.

Для автоматической проверки чтения в терминале (bash):

```bash
export SMOKE_BASE_URL='https://YOUR-APP.vercel.app'
npm run smoke
```

Используйте только доверенный адрес своего приложения. Скрипт не следует редиректам .
При включённой защите Vercel скрипт может получить ответ защиты до API; проверяйте приложение через разрешённую сессию браузера.
Скрипт не проверяет транзакционные записи, конкурентные продажи или реальные котировки; для них нужен список выше.

## 5. Если сборка красная

Откройте GitHub → Actions → последний Verify → красный шаг.
Для локального воспроизведения:

```bash
nvm install
nvm use
npm install --global npm@12.0.2
npm ci
npm run verify
```

- HTTP 503: задайте корректный UUID в DEFAULT_PORTFOLIO_ID.
- HTTP 404 Portfolio not found: выбранного ID нет в подключённой базе.
- HTTP 500: проверьте серверные переменные и логи Vercel.
- HTTP 502/ошибка RPC: проверьте доступность базы, миграцию, права и логи.
- `/api/*` возвращает HTML/404: проверьте корень проекта и наличие API-функций в деплое.
